# AGENTS.md

Static website for Martin Curkovic (DJ/producer). It replaces a GoDaddy site builder site and the
ToneDen smart links that were used for Instagram and Meta ads. Hosted free as static files
(GitHub Pages is the plan) with Martin's own domain pointed at it.

## Goals and constraints

- **Lightweight above all.** Many visitors are on slow connections. No frameworks, no web fonts,
  no animations, no third-party scripts except the optional Meta Pixel. Keep pages small.
- Plain HTML and CSS. The only JavaScript is `pixel.js`, and it does nothing until a Pixel ID is set.
- Mobile first and responsive. Test narrow widths.
- Use **relative paths** (`../style.css`, `img/...`) so the site works from any base URL.
- No contact form (deliberate, there is no backend). Contact is social links only
  (Instagram DMs for enquiries); Martin chose to keep his email off the site for now.

## Layout

- `index.html`: home page (hero, music, label, contact). The hero and the Music section show only the
  **latest release** (`RELEASES[0]`) plus a "Full discography" link.
- One folder per release (`middle/`, `putitdown/`, `believe/`, ...): a landing page for Meta ads, one per
  song. Folder names are the old ToneDen URL paths on purpose.
- `discog/`: the playlist landing page (Spotify/Apple playlist) plus a list of **every release**. It is the
  way visitors reach the older song pages, since the home page only shows the latest.
- `links/`: link-in-bio hub for the Instagram bio (latest release plus links to the discography and site).
- `404.html`, `robots.txt`, `sitemap.xml`: generated by `build.py`. GitHub Pages serves `404.html` for any
  unknown URL, even a nested one like `/a/b/`, so it is the one page that uses **root-based** paths
  (`/style.css`, `/discog/`) instead of relative ones. `robots.txt` allows everything (`/links/` is kept
  out of search by its `noindex` tag; blocking it would hide that tag from crawlers). `sitemap.xml` lists
  the public pages (not `/links/`, not 404) and only exists once `SITE_URL` is set.
- `style.css`: the only stylesheet. `pixel.js`: Meta Pixel and click tracking (Pixel ID set at the top).
- `app-links.js`: inside Instagram/Facebook/TikTok in-app browsers, opens Spotify in the app (tries the
  `data-app="spotify:track:ID"` link, falls back to the web link after 1.5 s). Regular browsers are untouched.
  `build.py` adds `data-app` to Spotify buttons automatically.
- `img/`: optimised WebP images used by the site. `src-images/`: originals, not served.
- `previews.js` and `previews/`: the tap-to-play preview on the cover art and the audio clips it plays.
- `tools/releases.py`: **the release data** (titles, credits, dates, links, covers, previews). Edit this.
- `tools/build.py`: generates every release page, `discog/`, `links/` and the hero and music block of
  `index.html` from `tools/releases.py`.
- `tools/optimize-images.py`: turns `src-images/` into `img/`.
- `tools/icons/`: platform logo SVGs from Simple Icons (CC0), inlined as `<svg>` next to each streaming
  button label by `build.py`. Icons are decorative (`aria-hidden`); the text label always stays.

## Generated files: do not hand-edit

The release pages, `discog/index.html`, `links/index.html` and the blocks between
`<!-- hero-release:start/end -->` and `<!-- releases:start/end -->` in `index.html` are written by
`tools/build.py`. Change the data in `tools/releases.py` (or the templates in `build.py`), run
`python3 tools/build.py`, and commit the output. Everything else in `index.html` and `style.css` is
edited by hand.

## Commands

```
python3 tools/build.py              # regenerate pages from the release data
python3 tools/optimize-images.py    # regenerate img/ from src-images/ (needs Pillow)
python3 -m http.server 8000         # preview at http://localhost:8000
```

Preview with the local server, not by opening files directly: folder links like `middle/` do not
resolve to `index.html` under `file://`.

## Adding a new release

**What Martin needs to provide** (ask for anything that is missing):

1. **Title and credited artists**, exactly as shown on Apple Music/Spotify. Check collaborators.
2. **Cover art**: square, at least 640x640 (the distributor's 3000x3000 original is ideal), JPG or PNG.
3. **Streaming links**, only for platforms where it is actually out: Spotify, Apple Music, Beatport,
   Bandcamp, SoundCloud, YouTube (or YouTube Music), Tidal, Deezer, Amazon Music. Beatport and Bandcamp
   are treated as the **extended mix** links (their own group on the page). Use clean URLs:
   strip tracking parameters (`at=`, `ct=`, `utm_*`, affiliate `tag=`) but **keep Spotify's `?si=`
   share token**. Tested in Safari on desktop: the link with `?si=` offered to open the app and the
   same link without it opened the web player. Get one from Spotify's Share, Copy link.
4. **Optional preview clip.** Tapping the cover art plays `previews/<slug>.mp3` (`previews.js`; set
   `preview="previews/<slug>.mp3"` on the release). Preferred: a clip cut from Martin's master (he picks
   the section; a WAV plus the start time is enough; about 96 kbps with short fades is roughly 360 KB
   for 30 s). The current clips are Spotify's own previews: fetch
   `https://open.spotify.com/embed/track/<id>`, read `audioPreview.url` from the `__NEXT_DATA__` JSON
   in the page, and download that mp3. In The Middle's Spotify clip is only about 15 s. A release
   with no `preview` just shows a plain cover with no play button (the Discography is a playlist, so
   it has none). Nothing is downloaded until someone taps.

**Steps**

1. Save the cover as `src-images/<key>.jpg` and run `python3 tools/optimize-images.py` (every jpg there
   becomes a 480 px WebP in `img/`).
2. Add an entry to `RELEASES` in `tools/releases.py`, **newest first**: `RELEASES[0]` is what the home page
   hero, the home page card and the `/links/` hub show, so a new entry becomes the "new release"
   everywhere automatically. Fields are documented at the top of that file. `slug` is the folder and URL
   path (short, lowercase). `platforms` are the main streaming buttons (Spotify first, it is the
   highlighted one; then Apple Music, YouTube Music, YouTube, SoundCloud, Tidal, Deezer, Amazon Music,
   Audiomack). `extended` holds the extended-mix links (Beatport, Bandcamp), shown under their own
   "Extended mix" heading. Pixel keys with icons: `spotify apple-music beatport soundcloud youtube
   youtube-music tidal deezer bandcamp amazon-music audiomack`.
3. Run `python3 tools/build.py`, preview with `python3 -m http.server 8000`, and click every link.
4. `git add` and suggest a commit message. The ad URL is `/<slug>/` on the live domain; the pixel
   reports `release=<key>` on each click. The release also appears in the Discography list automatically.

The existing pages were built from Martin's old ToneDen pages (the `window.preloadLink` JSON on
`martin.fanlink.tv/<slug>`), which hold titles, credits, covers, links and Spotify previews. ToneDen is
shutting down, so a new release has to be filled in from Martin's links instead.
